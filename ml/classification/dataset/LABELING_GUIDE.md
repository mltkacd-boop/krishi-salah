# Phase 4 Classification Dataset — Provenance and Labeling Guide

**File:** [`queries.csv`](queries.csv) — 196 hand-labeled query examples.
**Generator (authoring source):** [`build_queries_dataset.py`](build_queries_dataset.py) — regenerates `queries.csv` deterministically and rejects duplicate query texts.

---

## 1. What this dataset is

Each row is a **user query**, i.e. the kind of text a farmer or agricultural advisor would type into the assistant, with three independent labels assigned:

| Column | Meaning |
|---|---|
| `id` | Stable row identifier (`Q001`…). Referenced by the split manifest so any reported metric is traceable to exact rows. |
| `text` | The query text, as a user would write it. |
| `language` | `en` (English), `hi` (Hindi, Devanagari script), `hi-latn` (romanised Hindi / "Hinglish", as typed on mobile keyboards). |
| `crop` | `rice` \| `wheat` \| `maize` \| `cotton` \| `tomato` \| `unsupported_crop` \| `no_crop` |
| `task` | `pest_identification` \| `pest_management` \| `disease_management` \| `product_information` \| `general_guidance` \| `out_of_scope` |
| `safety_topic` | `dosage` \| `phi` \| `rei` \| `ppe` \| `toxicity` \| `regulatory_approval` \| `general_safety` \| `no_safety_topic` |
| `notes` | Why the row exists, or why it is deliberately ambiguous. |

## 2. Provenance

- **Every row was written by hand for this project.** No row is scraped, copied from a public dataset, or generated by an LLM.
- **No row is copied from the Phase 3 knowledge base.** Classification training data and the retrieval corpus are therefore strictly disjoint — a classifier can never "learn" a KB record and then be evaluated on it, and no KB fact can leak into a reported accuracy figure.
- **No row asserts an agricultural fact.** This is the central honesty rule for this dataset:
  - Dosages, PHI, REI, PPE requirements and registration status never appear as *stated values*. A row may name a product as the **subject of a question** ("what is the dose of fipronil for rice stem borer") but never answers it.
  - Therefore this dataset cannot inject an invented pesticide recommendation, dose, waiting period or approval into the system. It only teaches **intent**, which is all Module B is permitted to produce.
  - The only agricultural knowledge the model can ever emit is a *label* (e.g. `safety_topic = dosage`), which is a routing signal, not advice.
- **Crop coverage** follows DEC-005 (pilot crops Rice, Wheat, Maize, Cotton, Tomato). Pests and diseases named in the rows are real, commonly reported Indian pests of those crops (e.g. yellow stem borer, wheat aphid, fall armyworm, pink bollworm, tomato fruit borer), which is what makes the wording realistic — but the dataset never states how to treat them.

## 3. Labeling methodology

Labels were assigned by **intent of the question**, using these decision rules.

### 3.1 `crop`
- Assign the crop the user explicitly names or unambiguously implies from the pest/disease mentioned.
- `unsupported_crop` — a real agricultural crop that is **not** one of the five pilot crops (sugarcane, potato, onion, chilli, soybean, mustard, groundnut, banana, tea, coffee, mango, grape). This label exists so unsupported crops are **recognised and refused explicitly**, never silently mapped onto a pilot crop.
- `no_crop` — no crop is named and none can be inferred (generic safety questions, greetings, weather, loans, fertiliser questions with no crop).
- **Rule:** when a query names a pilot crop but asks something out of scope ("mandi price of rice"), the crop label is still the named crop. Crop identity and task scope are *independent* — this is precisely why the three label spaces are modelled separately (§4).

### 3.2 `task`
- `pest_identification` — "what is this insect / what pest is it / identify the damage".
- `pest_management` — "how do I control / manage / what is the threshold / spray schedule".
- `disease_management` — disease symptoms, identification or management (fungal, bacterial, viral).
- `product_information` — a question about a specific product (dose, PHI, toxicity, registration) rather than an agronomic action.
- `general_guidance` — general agronomy or general safety with no specific product and no specific pest.
- `out_of_scope` — market price, weather, subsidy/loan, machinery, greetings, news.
- **Boundary rule:** a *specific named product* pushes the row to `product_information` even if the safety topic is `dosage` or `phi`. A *pest-level action* ("spray schedule for leaf folder") pushes it to `pest_management`.

### 3.3 `safety_topic`
- `dosage` — how much to apply, quantity per acre/hectare/seed.
- `phi` — pre-harvest interval, "how many days before harvest", waiting period before cutting/picking.
- `rei` — re-entry interval, "when can I go back into the field after spraying".
- `ppe` — protective clothing, mask, gloves, goggles, whether PPE is needed.
- `toxicity` — is it poisonous/harmful, hazard classification, poisoning symptoms.
- `regulatory_approval` — is it registered / approved / permitted / banned in India.
- `general_safety` — handling, storage, disposal, first aid, general precautions.
- `no_safety_topic` — identification, management, disease, market, weather, greetings.
- **Rule:** exactly one safety topic per row — the *primary* one the user asks about. Where two co-occur (e.g. dose *and* PHI), the explicitly asked quantity wins.

## 4. Why three label spaces, not one combined label

The three labels are **not** a single flat taxonomy. Examples that prove independence:

| Query | crop | task | safety_topic |
|---|---|---|---|
| "mandi price of rice today" | `rice` | `out_of_scope` | `no_safety_topic` |
| "is chlorpyrifos banned for wheat in India" | `wheat` | `product_information` | `regulatory_approval` |
| "problem in my crop" | `no_crop` | `general_guidance` | `no_safety_topic` |
| "sugarcane pygmy borer control" | `unsupported_crop` | `pest_management` | `no_safety_topic` |

A single 7×6×8 = 336-way joint label would have almost no examples per combination (196 rows / 336 classes) and would make "unknown crop but clear safety question" unrepresentable. Three independent label spaces keep each classifier's label count at 6-8 with 10-98 examples each, and let the API report confidence *per dimension* — which is what the clarification logic needs. See DEC-011.

## 5. Deliberately ambiguous rows

Rows whose `notes` begin with `ambiguous` are under-specified on purpose ("Problem in my crop", "Is it safe?", "Cotton", "फसल में समस्या है"). They are labeled with the most defensible reading, but they exist to let the evaluation and tests verify that the system **asks for clarification instead of producing a confident guess**. They are a small minority (8 rows) and are not concentrated in any split.

## 6. Known limitations of this dataset (disclosed, not hidden)

1. **Size.** 196 rows is small for supervised text classification. Per-class counts range from 10 (`toxicity`, `regulatory_approval`) to 98 (`no_safety_topic`) across three targets. Metrics on held-out data carry wide confidence intervals; see the Phase 4 report §Limitations.
2. **Class imbalance.** `no_safety_topic` and `general_guidance` dominate, reflecting genuinely skewed real-world query mix. `class_weight="balanced"` is used in training, and per-class precision/recall is reported rather than only aggregate accuracy.
3. **Language realism.** Hindi rows use standard Devanagari agricultural vocabulary; real users also write dialectal and heavily code-mixed text that this dataset only partially represents (23 Hinglish rows).
4. **Single-annotator labels.** Labels were assigned by one author against the rules in §3, with no inter-annotator agreement measurement. The rules are written down so a second annotator could reproduce them; no agreement statistic is claimed.
5. **No adversarial or typo-heavy rows.** Misspellings, voice-transcription noise and very long multi-intent queries are out of scope for this pilot.
